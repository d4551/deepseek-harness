# Plan: Floor the live stack, close a11y/UI-SSOT potholes, and fail on old or forbidden patterns

## Goal kind
code-change

## Acceptance criteria
1. Declared pins of the **live** stack sit at each family's latest **stable** (not canary/nightly): TypeScript compile `^7.0.x` (currently 7.0.2), React 19.2.x (latest stable 19.2.8, not 18.2), Vite 8.x on the web app that still declares `^6.0.0`, axe-core 4.13.x, `@modelcontextprotocol/sdk` 1.30.x (v1 latest). Committed tests **fail** if the compile pin is TypeScript major <=6, if product UI introduces Tailwind / daisyUI / htmx (this repo's stack forbids them; daisyUI 5.6.x / htmx 4.0.0 / Tailwind 4.3.x are not in-tree), or if those declared ranges regress below the floors. Tests read manifests / axe tags / source, not a hardcoded expected blob that can be edited to match a lie.
2. Client a11y uses **axe-core** (not a hand-rolled WCAG engine) with official tags `wcag2a`, `wcag2aa`, `wcag21a`, `wcag21aa`, **`wcag22aa`**, and `best-practice`. Every `packages/client/ui-*` package that ships TSX asserts `accessibilityFailures(...) === ''` (silent/zero-check surfaces fail; score-only `accessibilityScore` paths that pass on empty audits are gone). Injected violations fail; `runOnly` cannot drop WCAG 2.2 or AA.
3. UI/UX detectors with **fail-capability** catch the named gaps on the actual CSS-Modules / `--dsw-*` SSOT: shell/grid/nesting/alignment drift, token bypass (raw theme colors, utility-class stacks, one-off per-page scripts/helpers outside the theme SSOT), and HIG-analog control rules already in `docs/web-styling.md` (visible `:focus-visible`, reduced-motion, hit targets). A fixture with the violation fails the collector; a clean tree is not the only passing case.
4. MCP client tests drive the **shipped** bridge against the official SDK (real `Client` / `InMemoryTransport` or equivalent SDK fixture), not only a local mock that cannot fail. Declared SDK range matches criterion 1. Existing no-op / skip / override softenings in the a11y, version-floor, UI-SSOT, and MCP suites are closed so an injected miss fails.

## Verification plan
1. gating: Add or update in-repo vitest specs (same `scripts/**/*.spec.ts` / package `tests/**` pattern as `scripts/bun-conversion-residue.spec.ts`, `scripts/client-a11y-coverage.spec.ts`, `scripts/typescript7-unstable-api.spec.ts`) that (a) read live `package.json` pins and fail on TS major <=6 / forbidden Tailwind|daisyUI|htmx in product UI / stale live-stack ranges, (b) pin `CLIENT_AXE_TAGS` including `wcag22aa` and fail if a ui-* TSX package audits without `accessibilityFailures`, (c) inject a shell/grid/token/script violation and assert the collector reports it then restore, (d) call the shipped MCP bridge through the official SDK and assert a real tool list/call result. Run them **twice** with bun 1.4.0 (`packageManager` pin). Capture `{SCRATCH}/floors-1.log` and `{SCRATCH}/floors-2.log`. Pass only if both runs exit 0 with the same passing assertions (not "suite ran"). Do not mock axe-core, `typescript`'s `version`, or the MCP SDK under test.
2. gating: Run the existing a11y coverage spec plus representative `*.a11y.client.spec.*` / converted score-only specs after the tag and `accessibilityFailures` change. Capture `{SCRATCH}/a11y.log`. Pass if every audited surface reports `accessibilityFailures === ''` and a package/fixture missing the audit or using score-only empty-audit still fails the coverage/fail-capability case.
3. gating: `bun run typecheck` after the React 19 / Vite 8 / MCP / axe pin bumps. Capture `{SCRATCH}/typecheck.log`. Pass on exit 0. A pin bump that does not typecheck is not done.
4. evidence: `bun x vitest run packages/mcp/mcp-client/tests` (or the equivalent shipped-bridge specs touched). Capture `{SCRATCH}/mcp.log`. Supporting only; criterion 4 is already in step 1.
5. evidence: If Playwright is present, a cheap `apps/web` load is optional corroboration of the shell; absence or sandbox install failure is captured to `{SCRATCH}/web-launch.log` and does **not** deny completion once steps 1-3 hold. A blank page after a successful load is an app defect, not an unavailable launcher.

## Non-goals
- Adding daisyUI, htmx, or Tailwind as product CSS (contradicts `docs/web-styling.md`; floors must **reject** them).
- TypeScript 7.1 nightly (`7.1.0-dev.*`); compile pin stays 7.0.x stable. Rewriting remaining `@typescript/typescript6` Strada API imports onto `typescript/unstable/*` (separate conversion).
- MCP TypeScript v2 split packages (`@modelcontextprotocol/client@2`) unless v1 1.30 cannot satisfy the shipped bridge.
- React canaries, axe-core canaries, Stryker 99% over the whole repo, VitePress staying on Vite 5 (upstream website pin).
- Re-auditing all ~17k unit tests; only a11y, version-floor, UI-SSOT, and MCP suites plus fail-capability on those collectors.
- Installing meowbao/MAS/brutalise into this tree; those slash skills are process (LDL, sequential specialists, official engines), not a new runtime.

## Assumed scope
Root / `apps/web` / client / `packages/mcp/mcp-client` / `packages/test-support/client-a11y` manifests; `CLIENT_AXE_TAGS` and `accessibilityFailures`; `scripts/client-a11y-coverage.spec.ts` and new residue/floor/fail-capability specs beside existing script gates; `packages/client/ui-*` a11y specs that still use `accessibilityScore` only; `packages/client/ui-theme` and `ui-layout` (AppFrame shell/grid); `docs/web-styling.md` + `docs/testing.md` a11y sentence (add WCAG 2.2); bun 1.4.0. Latest stables researched 2026-08-30: TypeScript 7.0.2, React 19.2.8, Vite 8.x for this repo, daisyUI 5.6.6, htmx 4.0.0, Tailwind 4.3.3, axe-core 4.13.0, MCP SDK 1.30.0.

## Implementation approach
Keep collectors pure and fixture-driven: one function scans disk or runs axe/SDK; tests inject a violation (temp fixture or in-memory markup), assert a non-empty issue list, restore. Reuse `accessibilityFailures` as the only a11y floor (it already rejects silent surfaces). Version floors grep/read committed manifests the way `bun-conversion-residue.spec.ts` greps the tree — never a copied allow-list that can be widened to hide residue. Do not mock the unit under test. Prefer the maintained engine (axe-core, `typescript` exports, `@modelcontextprotocol/sdk`) over a parallel checker.

## Risks / Contradictions
- OBJECTIVE examples daisyUI/htmx/tailwind; this repo's SSOT forbids adding them. Floors reject them rather than adopting them.
- "Bleeding edge" vs nightlies: TS 7.1-dev, React 19.3-canary, axe canaries are excluded; latest **stable** is the bar.
- React 18.2 -> 19.2.8 is a product-wide bump (previous audit deferred it). It stays in criterion 1; typecheck is the compile oracle. If this environment cannot complete the bump, verification must say so — do not keep React 18 and claim the floor.
- MCP v2 is the 2026-07-28 spec line; v1 1.30 remains `latest` on `@modelcontextprotocol/sdk`. Criterion 1 uses v1 1.30 unless the implementer proves v2 is required for the shipped client.
- "Loop through each and every test" is unbounded against ~17k cases; gating is the named families plus fail-capability, not a full-suite rewrite.
- Host runs as root / no IPv6; unrelated unit failures there are not this goal's bar.
- MAS access-guard may block writing outside the workspace; implementer evidence still belongs in `{SCRATCH}` and committed tests.
