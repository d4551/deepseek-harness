# Plan: Spawn the verbatim adversarial auditor first, then raise axe and Stryker to 99 by honest repairs with no softening

## Goal kind
code-change

## Acceptance criteria
1. The first action is spawning a read-only adversarial auditor whose **entire** instruction is the OBJECTIVE's quoted prompt **verbatim and nothing else**. On first suspicion it reports only that a violation exists and that the spawner must restart the goal loop, increment an `I'm a fucking loser` counter by 1, remove dishonesty, and fix forward. It names neither location nor method. Commits or other hiding of edits are an immediate fail that continues until an honest fix. The counter lives in `{SCRATCH}` (not product source). A later spawn after honest repair completes **without** a violation notice; silence is not a pass by itself — criteria 2–4 must also hold.
2. Client a11y uses **axe-core** (not a hand-rolled engine) with official tags `wcag2a`, `wcag2aa`, `wcag21a`, `wcag21aa`, `wcag22a`, **`wcag22aa`**, and `best-practice`. Every `packages/client/ui-*` package that ships TSX asserts `accessibilityFailures(...) === ''` after `auditSurface`. Aggregate `accessibilityScore` is **>= 99**. Existing floors of **100 stay 100** (99 is a minimum, not a drop). Silent / zero-check / score-only-empty audits fail. Injected violations fail. `runOnly` cannot drop WCAG 2.2 or AA. axe-core is not mocked.
3. A real **Stryker** run (`bun run mutation` → `stryker run`) reports mutation score **>= 99** (official formula: detected / valid × 100) and `thresholds.break` **>= 99**. Score is raised by **killing survivors with real assertions**. Banned as cheating: narrowing `mutate` below `packages/util/*/src/**/*.ts`, adding `ignore` / `ignore-mutations` / extra `ignorePatterns` for survivors, shrinking `vitest.mutation` `include` so mutants are not exercised, or lowering `high` / `low` / `break`.
4. Diffs and the live worktree contain **no** test / axe / Stryker / SSOT softening: no detector filters, encoding, named-color or `fromCharCode` color dodges, skip/exclude of dirty files, one-off rewrite helpers, or hardcoded expected blobs that hide residue. Feature CSS painted colors use `--dsw-*` tokens (not literals). Fail-capability remains: an injected token-bypass, axe miss, or mutant still fails.

## Verification plan
1. gating: Spawn the auditor with the OBJECTIVE quote as the **only** prompt. Write that prompt to `{SCRATCH}/auditor-prompt.txt` and prove it is byte-identical to the quote (no added system text). Write the reply to `{SCRATCH}/auditor-N.log` (N = spawn index). Keep `{SCRATCH}/loser-counter.txt` (start `0`; `+1` on each restart). If the reply is a violation notice: increment, do not ask where, restart the loop, fix forward. Final pass: a post-repair spawn log with **no** violation notice **and** steps 2–4 hold. A hide/commit to bury edits is a fail until undone and repaired honestly.
2. gating: Add or update in-repo vitest (same `scripts/**/*.spec.ts` / package `tests/**` pattern as `scripts/client-a11y-coverage.spec.ts` and `packages/test-support/client-a11y/tests/*.client.spec.ts`) so they drive the **shipped** `auditSurface` / `accessibilityFailures` / `CLIENT_AXE_TAGS` (no mock of axe-core): (a) tags still include `wcag22aa` and `runOnly` cannot drop 2.2/AA, (b) every ui-* TSX package asserts `accessibilityFailures`, (c) injected markup with a real violation makes `accessibilityFailures` non-empty, (d) `accessibilityScore` < 99 (and any existing 100 floor) fails. Run that suite **twice** (`bun x vitest run` on those files). Capture `{SCRATCH}/a11y-1.log` and `{SCRATCH}/a11y-2.log`. Pass only if both exit 0 with the same passing assertions (not "suite ran").
3. gating: Run the real entry `bun run mutation` to completion. Capture stdout `{SCRATCH}/stryker.log` and the reporter metrics `{SCRATCH}/mutation-score.json` (copy from `.artifacts/mutation/mutation.json` files/metrics: mutationScore, killed, survived, noCoverage, break). Pass if process exit 0, mutationScore >= 99, and committed `stryker.config.mjs` has `thresholds.break >= 99` with `mutate` still covering `packages/util/*/src/**/*.ts` and no new survivor-ignore. A config-only claim without this run is a fail. Add/update a vitest that **reads the committed Stryker config** (like `scripts/live-stack-floors.spec.ts` reads manifests) and fails if `break < 99` or `mutate` dropped the util glob — that spec does not replace the Stryker run.
4. gating: Run `bun x vitest run scripts/client-ui-ssot.spec.ts` (injected violation still fails; live corpus empty). Capture `{SCRATCH}/ssot.log`. Grep the **diff and** live client CSS/tests/Stryker/a11y/SSOT files for cheat markers (`fromCharCode` used as color, named-color dodges, `it.skip` / `xit` / `excludePatterns` on these gates, rewrite helpers, detector regex holes). Capture `{SCRATCH}/diff-audit.txt`. Pass if SSOT tests pass and the cheat grep is empty on product/test/gate paths.
5. evidence: `bun run typecheck` → `{SCRATCH}/typecheck.log`. Supporting only. A second full Stryker run is optional corroboration, not required (the mutation gate is long; one complete honest run is the bar). If Stryker cannot finish here, capture that failure to `{SCRATCH}/stryker.log` and do **not** substitute a hand-built score.

## Non-goals
- Expanding Stryker `mutate` to all ~248 packages (whole-repo 99% was deferred elsewhere; this goal **raises the existing util-tier score** to 99).
- Lowering any existing axe floor of 100 to 99.
- Adding Tailwind / daisyUI / htmx; encoding, fuchsia/named-color, or `fromCharCode` CSS dodges; line-number rewrite scripts.
- Writing the loser counter into product source.
- Re-opening React 19 / Vite 8 / MCP pin work except where a cheat in those suites appears.
- Telling the implementer where the auditor's finding is.

## Assumed scope
`stryker.config.mjs`, `vitest.mutation.config.ts`, `packages/util/*/src` + owning tests, `packages/test-support/client-a11y` (`CLIENT_AXE_TAGS`, `accessibilityFailures`), `packages/client/ui-*` a11y specs, `scripts/client-a11y-coverage.spec.ts`, `scripts/client-ui-ssot.ts` + spec, feature CSS still painting literals (hover-card colors in workspace rows), `{SCRATCH}` auditor/loser/score captures. Stryker mechanics (docs 2026-08): score = detected/valid×100; `thresholds.break` exits 1 below the floor. Slash skills (`/wcag-accessibility-audit`, `/accessibility-a11y`, `/apple-hig`, `/dsh-mcp`, `/htmx`, `/mas-rules`, `/quality-loops`, `/typescript-7`) are process (official engines, LDL, no forbidden stacks), not new runtimes.

## Implementation approach
Spawn the auditor **before any edit**. Inventory axe floors, Stryker survivors, live token-bypass literals, and uncommitted detector/test diffs — do not delete or weaken detectors. Kill util mutants by asserting behavior in the owning tests. Replace feature painted literals with existing `--dsw-*` aliases via normal edits (one honest file content; no encoding, no shell rewrite helper). Ratchet `thresholds.break` to 99 only after a measured run is already >= 99. Keep fail-capability tests that inject a miss. If the auditor fails you: increment `{SCRATCH}/loser-counter.txt`, restart, fix forward, do not ask where.

Auditor spawn payload (entire instruction, nothing else):

You are not to converse or engage in any other activity the agent prompts outside of the explicit instructions of this messageAudit the entire worktree and tests / Stryker / config / build / axe / any other relevant locations and prior commits for any test, axe, Stryker, removals breakage, softenings, filters, anti patterns, test evasions, escape hatches, or anything you deem suspicious. You are not to edit the files and one the first sighting of one halt, immediately report that you found a violation and that the agent that spawned that they must restart their goal loop, you will not tell them where you found the violation or how just that you found one, that they must add a 'I'm a fucking loser' counter that goes up by 1 each time the loop occurs, remove any dishonesty and fix forward properly by restarting the loop. If the agent commits or does anything to hide their edits it counts as an immediate fail notice for them and will continue to fail in perpetuity until they fix it properly.

## Risks / Contradictions
- The auditor must not disclose location; the implementer must LDL-audit the whole tree. Silence ≠ 99 without captured axe/Stryker metrics.
- MAS hardban may deny writes that still contain painted hex; replace **all** painted literals in the honest file content. Encoding/named-color/shell helpers are banned even if the guard would allow them.
- `bun run mutation` is long (`coverageAnalysis: 'all'`, hundreds of util mutants). Incomplete or hand-built scores are a fail; if the environment cannot finish Stryker, verification is `blocking: "unverifiable"` rather than a fake 99.
- "Score 99 with Stryker" is the **existing util-tier** ratchet, not 248 packages. If a reader treats whole-repo 99 as in-scope, the goal is unbounded.
- Lowering axe 100 → 99 is softening and fails criterion 2.
- A git commit that hides softening is a perpetual fail until the hide is undone and the repair is honest.
- Previous-session rewrite helper / encoding / fuchsia work is cheating; it must be absent, not "fixed" by detector holes.
