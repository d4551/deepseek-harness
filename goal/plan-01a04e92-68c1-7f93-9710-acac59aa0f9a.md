# Plan: Audit that bun 1.4.0 and TypeScript 7 compile conversion is complete and matches the shipped notes

## Goal kind
analysis

## Acceptance criteria
1. The executable install/run surface (`packageManager`, `bun.lock`, GitHub/GitLab CI, lefthook, package scripts, apps/, native/) does not drive `pnpm`; `scripts/bun-conversion-residue.spec.ts` reports zero unaccounted `pnpm` hits on that surface.
2. Host and Client compile pins are `typescript` `^7.0.2`; compiler-API consumers import `@typescript/typescript6` rather than `typescript` for programmatic `ts` (the TypeScript 7.0 decision).
3. Every remaining tracked `pnpm` mention falls only in the residue spec's accounted categories (archived notes, named historical implemented notes, conversion records, external-tool facts, client test fixtures).
4. `bun run typecheck` exits 0 on this tree (Host `tsc -b tsconfig.host.json` plus Client `tsc -b tsconfig.client.json`).

## Verification plan
1. gating: Run `bun x vitest run scripts/bun-conversion-residue.spec.ts` with bun 1.4.0 (the `packageManager` pin; 1.3.x cannot parse `bun.lock` lockfileVersion 2). Capture `{SCRATCH}/residue.log`. Pass only if all cases pass, including empty unaccounted list and empty executable-surface list.
2. gating: Read root `package.json` `packageManager` and `devDependencies.typescript`. Grep `"typescript":` in workspace `package.json` files and `from '@typescript/typescript6'` in scripts/Typert. Capture `{SCRATCH}/ts-pins.txt`. Pass if compile pins are `^7.0.2` and compiler-API files import `@typescript/typescript6`.
3. gating: Run `bun run typecheck` (same bun 1.4.0). Capture `{SCRATCH}/typecheck.log`. Pass on exit 0.
4. evidence: `git grep -l -- pnpm` on `.github/workflows/`, `.gitlab-ci.yml`, `lefthook.yml`, `package.json` files; capture `{SCRATCH}/pnpm-executable-grep.txt`. Should be empty on those paths (residue spec already gates this).
5. evidence: Quote the conversion notes (`.agents/notes/implemented/process/2026-08-29-bun-package-manager.md`, `.agents/notes/implemented/process/2026-08-29-typescript-7-compiler.md`) for any remaining allowed `pnpm` or typescript6 exceptions so the audit names them rather than treating them as unfinished conversion.

## Non-goals

- Replacing `@typescript/typescript6` with a TypeScript 7.1 compiler API.
- Switching product runtime from Node to bun.

- Rewriting archived Agent Notes that still mention pnpm.

## Assumed scope
Root `package.json`, `bun.lock`, `bunfig.toml`; `scripts/bun-conversion-residue.spec.ts`; GitHub/GitLab CI and lefthook; Host/Client tsconfigs; Typert/gate scripts importing `@typescript/typescript6`; the two implemented conversion Agent Notes and `.agents/upgrade-baseline.md`.

## Risks / Contradictions
- Local `bun` 1.3.x cannot parse this lockfile; the audit must use bun 1.4.0 (pin or `/tmp/bun-1.4.0` binary already extracted).
- `bun run typecheck` is a full Host+Client compile; it is the conversion gate, not a substitute for the 17k-test suite. Known environmental unit failures (root permissions, IPv6) are out of this audit's contract.
- Website VitePress still pins vite 5 by upstream need; that is not a bun/ts7 conversion miss.
