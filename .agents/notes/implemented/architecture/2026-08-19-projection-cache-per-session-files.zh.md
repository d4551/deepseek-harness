# Agent Note: 投影缓存改为每会话文件

Status: implemented

[English](2026-08-19-projection-cache-per-session-files.md) | 中文

## 问题

持久投影缓存曾是单个全局 `session_projcache.json`——存储根目录下一个文件里的 `sessions` 表。每次节流检查点都会重写包含所有会话行的整个文件，写放大随会话数量增长；且一个畸形文件会让整个缓存一起失效。

## 决策

缓存以 `per-record` 布局打开 `session_projcache` 存储域：每个会话一个带版本戳的文档，位于 `<root>/session_projcache/sessions/<id>.json`，介质归存储栈所有。[共享 base 组合包](../../../../packages/bundle/base/cordis.patch.yml)挂载 `storage`、`storage-json`、`storage-domain` 和缓存，JSON 根目录设为 `dshHomePath('storages')`。所有随附且基于 base 的 profile 都保持启用缓存，因此会话生产方会记录检查点，不取决于当前应用是否提供列表接口；不使用 base 组合包的 `sdk-minimal` 不在此装配范围内。缓存不定位或读取会话日志产物；消费方向其重建方法提供历史。

读写共享同一份一致状态：每次 `cachedSnapshot` 读取都是对域内存表的同步查找；每次写入排进该域的单条写链，仅在持久化后修改内存。会话创建、`turn/end` 和 dispose（资源释放）时必须写检查点，其间由计数和间隔触发写入。消费方向 `coldSnapshot` 提供权威历史，进行重建和持久写回；写回失败会记录警告，并让下次读取再次重建。JSON 后端请求仅属主目录权限（`0o700`）。

## 后果

- 每会话写入隔离：每次节流写入只替换该会话的小文档，消除全局写放大。域写链将写入串行化，新切面绝不会先于旧切面落盘；域关闭时会排空在途写入。
- 列表读取是同步内存读；没有记录文档的会话只是缺少投影列。
- ACP、headless、SDK 与 Web 会话都会发布缓存行，供后续消费方使用。确保日志领先的持久性屏障可能按缓存节奏 flush 已覆盖的前缀，并拆分原本会合并的物理 JSONL 行；各 profile 的录制快照会重新 pack 逻辑事件流，因此缓存时序不会决定 fixture 布局。
- JSON 后端将格式错误、版本陈旧或不可读的记录文档视为缺失，但不删除它们。对于已加载但不符合检查点 schema 的值，领域显式声明的 `rebuildable: true` 表策略只持久删除该记录并记录其位置；相邻有效记录得以保留。[存储根目录与恢复决策](2026-07-28-storage-root-and-derived-medium-recovery.zh.md)负责该策略及其权威数据保护。unit/表读取失败和恢复删除失败会拒绝打开；占据记录路径的目录不会被自动修复。
- JSON 后端仅在目录树缺少持久初始化状态且枚举未发现已声明文档路径时导入整单元缓存。它在持久捕获完整导入快照前校验每个已声明表与路径安全键。中断的导入完成该快照后才允许读取或修改；关闭会排空初始化。初始化完成后，即使所有记录被删除，目录树仍是权威状态，而缺失会话行从日志重折叠。已有无标记文档路径即使不可读或版本陈旧，也会确立目录树权威状态。源文件保持不变。
- 删除以原子方式发布一份小型带版本的不存在文档，替换检查点值。它与 put 使用相同的持久发布协议；后续 put 替换该不存在文档。创建目录会在报告发布成功前持久化祖先目录项。初始化元数据损坏会拒绝访问，而不会授权重新导入。
- 缓存记录绑定其日志生命周期：存储的 `{createdAt, cwd}` 身份防止被重建的 id 误导。

## 验证

[缓存恢复测试](../../../../packages/session/session-projection-cache/tests/recovery.spec.ts)通过真实 Loader 和 JSON/JSONL 服务跨重启运行。测试验证不符合 schema 的记录删除、从未改变的历史重建、保留相邻有效记录与工作区字节、替换格式错误/版本陈旧的文档、替换不可读的普通文件，以及删除失败。本地运行覆盖 macOS；原生 Windows 权限分支仍未在本地验证。这是针对具体行为的证据，不代表整体覆盖率或变异测试结果。

[初始化恢复测试](../../../../packages/storage/storage-json/tests/initialization-recovery.spec.ts)通过真实文件系统阻塞验证中断的导入、不可变捕获输入、最后一条记录的删除、直接修改、关闭所有权及不安全元数据拒绝。[原生发布跟踪](../../../../packages/storage/storage-json/tests/record-durability.spec.ts)在 POSIX 上检查文件与祖先目录的成功刷写顺序。这些检查不模拟物理断电。

## 备选方案

- **保留全局 sessions 表。** 保留一次加载式列表，但保留了促成此改动的全局写放大与单文件爆炸半径。
- **缓存自持的每会话文件**（`<root>/<session-id>/projection_cache.json`）。这会让缓存负责路径、写链、在途跟踪、文件权限和后端特有行为。每次列表查询读取这些文件而写入采用节流，也会使列表读取落后于缓存状态。存储域统一负责持久性和一致读取。
- **经 `sessionPersistence.locate(meta)` 解析路径**（文件放在会话日志旁）。未采用：缓存得从日志 artifact 路径"猜"日志旁边（`dirname` + 固定文件名），把缓存耦合到持久化服务与后端的布局。
- **把 `per-record` 做成既有单元的一种模式而非独立单元类。** 未采用：两种布局的记录状态所有者不同——`single` 保存已提交的内存并发布整文件，`per-record` 则在其拥有的初始化完成后从目录重建记录。它们仍是同一后端下的两个小型独立类，记录键做路径安全校验而非编码。
