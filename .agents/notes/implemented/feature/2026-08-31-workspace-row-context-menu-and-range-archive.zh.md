# Agent Note: Workspace row context menu and range archive

Status: implemented

[English](2026-08-31-workspace-row-context-menu-and-range-archive.md) | 中文

## 问题

侧边栏浏览区里每一个操作项都只有一条入口：一枚 16px 的 **...** 按钮，且仅在指针停留于该行时才出现。要执行 Rename、Fork 或 Archive，就得先悬停到正确的行、找到按钮、再点击它——而桌面列表普遍响应的右击在这里毫无反应。归档同样严格按行进行，因此清理一串已完成的 Session，每一个都要各付出一次悬停、一次按钮点击和一次菜单选择。

## 决策

两种行都会在行内任意位置响应右击，打开与 **...** 按钮相同的菜单。`packages/client/ui-workspace/src/client/rows/Rows.tsx` 中的 `useRowMenu` 为二者统一持有这份状态：它保存打开标志，以及右击打开菜单时的指针位置。它向 `Menu` 传入返回该指针处零尺寸 `DOMRect` 的 `getAnchorRect`，使菜单落在光标之下，而不是落在那枚只在悬停时显现的按钮处；从按钮打开时指针位置被丢弃，`Menu` 一如既往地测量自身包裹元素。没有操作项的行保留平台自带菜单：临时的空白 **New Session** 行根本不渲染尾部操作区，Ungrouped 分组头也没有对应的 Workspace。

两种行共用一份范围选择，由 `packages/client/ui-workspace/src/client/selection.ts` 中的 `useRowSelection` 持有。分组树与扁平列表各自拥有一份选择，以各自按渲染顺序渲染出的行为键。在分组树中，该账目是每个真实 Workspace 分组头及其下的会话行，因此点击一个项目、再按住 Shift 点击更下方的项目，会选中两者之间的一切——分组头与会话一视同仁——正如操作者阅读列表的方式。Ungrouped 分组不进入账目：它没有对应的 Workspace，也没有行操作项。键自带种类前缀（`session:` / `workspace:`），因此两个 id 空间不会在同一份有序账目中相撞。

普通点击确定范围锚点并清空选择，然后该行才做它自己的事——打开 Session，或折叠项目。Shift 点击选中自锚点起的闭区间切片；Ctrl/Cmd 点击增删单行并重设锚点；Escape 通过 document 监听器撤销选择——因为这些行不可获得焦点，列表本身也没有键盘席位。成员关系在读取时对照已渲染的键重新核对，因此被归档、被折叠或被搜索过滤掉的行会自动离开选择，无需单独的核对流程。在选择之外的行上右击，会先把选择收窄到该行，这是平台通行规则。

被选中的 Workspace 行代表它的成员，为此 `GroupNode` 携带 `memberIds`：分组级操作所能触及的全部会话，按本地顺序排列，与展开状态无关，并排除临时的空白 New Session。折叠的项目因此仍能代表其会话，而不是什么都不贡献。由于落在范围中间的分组头可能触及操作者从未点击过的会话，标记依据的是触及范围而非原始成员关系：会话行只要在解析出的集合中就会被标记，于是被高亮的行恰好就是批量操作会归档的行，被选中的项目也在视觉上明确认领了它的成员。

选中两行及以上时，列表中每个行菜单都去掉其逐行操作项——Rename、Fork、Delete 与单行 Archive 都只针对一行——改为一行 **Archive N sessions**。`N` 统计触及的 Session 数，而非选中的行数；当一段只含空项目的范围触及不到任何 Session 时，该项处于不可用状态而非消失。提交它会按渲染顺序去重后为每个触及的 id 各调用一次 `archiveSession`，并立即清空选择，而不等待那个让行消失的归档集合回声。这里没有新增线上操作：`workspace.archiveSession` 接受单个 Session，注册表把写入串行化在同一条操作链后，且每次响应都携带完整的归档集合，因此无论调用以何种顺序落定，最后到达的回声都是正确的。选择属于临时视图状态，从不持久化；它随挂载的列表一同消亡，包括在分组与扁平两种呈现之间切换时。

选中的行带上 `css.multiSelected`——悬停填充加一条前导强调线，使一段连续选择读起来是一个整体，并与可能重叠的单个当前 Session 高亮区分开——并给出 `aria-selected`；两个列表容器都声明 `aria-multiselectable`。一处视觉隐藏的 `role="status"` 播报触及的 Session 计数，因为标记是仅有的另一条通道。

## 备选方案

**新增批量 `archiveSessions` 线上操作。** 已否决：相对于 N 次调用的扇出，客户端并无所得。注册表本就把归档写入串行化在同一条链后，且每次响应都携带完整集合，因此批量调用换来的原子性没有任何界面依赖，代价却是在 Typert 图、两个 SDK 及其预期输出中新增一种请求类型。

**把范围限制在会话行。** 已否决：这未能满足需求本身——需求正是点击一个项目、再 Shift 点击更下方的项目。它也显得武断：分组头就是同一个列表里的一行，处在同一个指针之下、同一份阅读顺序之中。

**让被选中的分组头贡献成员却不标记它们。** 已否决：落在范围中间的分组头会归档操作者 Shift 点击位置以下的会话，而这些会话不在任何高亮之内。以解析出的触及范围驱动标记，可使可见选择与提交集合始终是同一个集合。

**归档 Workspace 本身。** 已否决：不存在这样的操作——Workspace 只有 Delete，那是移除一条注册记录，并非批量归档的含义。被选中的项目解析为它的 Session，Workspace 注册记录不受影响。

**在批量项之外保留逐行操作项。** 已否决：Rename 与 Fork 针对单个 Session，在选中三行时提供它们会让目标无从确定。加宽后的菜单只保留对集合有定义的那一个操作。

**为 `Menu` 增加一等的按点定位模式。** 已否决：现有的 `getAnchorRect` 出口已经表达了"对着这个矩形定位"，而指针处的零尺寸矩形正是如此。在这个基础组件里再加一种定位模式，只会有一个调用方。

**给搜索结果加上选择。** 已否决：结果列表是对查询的排序投影，而非具有稳定顺序的账目，且它的行点击即导航。

## 影响

右击可以够到每一个行操作项，无需悬停搜寻；清理一串已完成的 Session——或若干整个项目——变成一次点击、一次 Shift 点击和一次菜单选择，而不是 N 次悬停。批量归档会为每个触及的 Session 各扇出一个请求，因此覆盖大项目的范围会引发一阵 RPC 突发；目前没有任何上限，而每次拒绝都会记录与单行操作相同的非致命 `session archive rejected:` 诊断。项目行上的普通点击既确定范围锚点也折叠分组，因为确定锚点不应夺走该次点击原有的含义。Escape 现在会在文档任意位置清空实时选择，同一次按键也会关闭已打开的行菜单。

单元覆盖直接钉住 `rowRange`、键的命名空间与各项选择手势（`packages/client/ui-workspace/tests/selection.client.spec.tsx`）；`tests/tree.client.spec.ts` 钉住折叠分组仍报告其成员，以及空白草稿与已归档行永不进入成员集合。行为覆盖钉住指针定位、空白行与分组头的豁免、两种行上带修饰键的点击路由，以及加宽后的菜单（含其单数标签与不可用的空集情形）（`tests/rows.client.spec.tsx`）。装配后的浏览器覆盖钉住单个分组内的会话范围、跨三个折叠项目的项目到项目范围按渲染顺序归档其全部四个 Session、被选中项目所认领的成员标记，以及扁平列表的 Ctrl 挑选与其 Escape 撤销（`tests/workspace-browser.client.spec.tsx`）。
