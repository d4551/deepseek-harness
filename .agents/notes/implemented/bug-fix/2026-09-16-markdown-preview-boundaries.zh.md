# Agent Note: Markdown 预览边界与可读的轨迹标签

Status: implemented

[English](2026-09-16-markdown-preview-boundaries.md) | 中文

## 问题

Markdown 脚注可以包含多个段落和代码块。将其子节点视为行内文本会让轨迹预览中相邻的词连在一起。消息标签的紫色文字在带色背景上的对比度也只有 3.69:1，低于原生 axe 测得的 4.5:1 文字要求。

## 决策

纯文本提取器使用解析器的 `mdast.Nodes` 契约，并在轨迹消费者压缩空白前保留脚注块之间的分隔符。它共用[增量渲染器的 GFM 语法](../architecture/2026-08-06-web-markdown-incremental-ast-renderer.zh.md)；解析器和渲染器保持现有的职责归属。

轨迹消息标签在主题背景上使用规范的主标签前景色。单元格内边距、行间隔、行圆角和边框在语义匹配处使用现有的集中令牌。

## 测试

提取器的 26 项真实解析器测试达到语句、分支、函数和行覆盖率各 100%。限定范围的 Stryker 变异测试杀死了 `plain-text.ts` 中全部 89 个变异体，得分 100%；这是提取器的结果，不是仓库得分。

四项原生 Chromium 用例在明暗主题下，以 640 和 1280 像素宽度运行 `trajectoryPreviewText` 并渲染单元格。它们要求脚注词语保持分隔、预览宽度大于零，且 axe 违规和未完成检查均为零。这些检查覆盖被测预览界面，并不覆盖所有轨迹类型或应用流程。

## 考虑过的替代方案

**将脚注展平为行内内容。** 这会在空白压缩能够保留词语间隔之前丢失段落边界。

**保留宽松的本地 AST 结构。** 可选字段重复了字段必填的解析器契约，并诱使代码处理解析器不可能产生的状态。

**保留紫色前景混色。** 其测得的对比度不满足文字要求；主标签令牌提供主题中的可读文字颜色。

## 影响

预览词语在脚注块之间保持分隔。消息标签放弃紫色前景色调，同时保留主题背景。现有的单元格几何尺寸和其他混色公式仍缺少匹配的规范定义；这些令牌变更不代表已经完成设计系统迁移。
