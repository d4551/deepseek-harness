# Agent Note: 根 agent 请求预算与用户可调上限

Status: implemented

[English](2026-09-16-root-request-budget-and-user-settings.md) | 中文

## 问题

把委派 agent（智能体）的上限同时用于根 agent，会使任务在发出 32 次请求后停止，即使共享额度为 128。用户明确发送后续消息可以开启新的计费阶段，但根 agent 仍会再次过早触及同一上限。策略值只能由部署配置提供，也使用户无法通过设置调整有限的请求上限。

## 决策

[会话计费模块](../../../../packages/core/session/src/request-budget.ts)按整个任务的共享上限限制根 agent。每个委派 agent 仍同时受自身上限和共享上限约束。上限分别为 32 和 128 时，一个委派 agent 可以使用 32 次请求，根 agent 可以使用剩余的 96 次；两者的总用量不能超过 128。

可选的 agent loop（智能体循环）部署策略建立一次[宿主设置注册](../../../../packages/core/agent-loop/src/request-budget-settings.ts)。部署配置提供计费身份和默认上限。用户只能修改两个正安全整数上限，且委派 agent 的上限不能超过整个任务的上限。系统拒绝由 agent 发起的设置写入。缺少配置时不会创建请求预算命名空间；持久化设置无效时策略保持不可用，Meowbao 请求中间件会拒绝这种状态。

[模型请求预算卡片](../../../../packages/client/ui-settings-plugins/src/client/RequestBudgetCard.tsx)暂存两个上限，并通过现有设置服务一起保存。放弃修改会恢复已提交的值；重置会暂存宿主提供的默认值。保存失败时保留草稿。卡片位于插件设置页面的「Agent 与执行设置」分组。

命名空间注册变化会通知共享设置镜像，因此加载或卸载策略后，卡片无需重新加载页面即可更新。spine 组合把可选的部署策略传给其 agent-loop 模块；未提供时仍保持缺失。生成的配置目录和服务目录描述这些公开契约。

每次请求预留读取已提交的上限，同时保留当前计费阶段的身份和已记录用量。保存设置既不接纳人工消息，也不恢复已暂停的任务。预留一旦被接受，取消、提供方失败以及后续上限修改都不会撤销计费。现有计费阶段事件和请求尝试事件保留原有格式。

## 考虑过的替代方案

**仅提高部署默认值。** 这仍会让根 agent 受错误的上限约束，也无法让用户控制任务的有限额度。

**在额度耗尽后自动开启新的计费阶段。** 这会移除明确的人工接纳边界，使重复的自动工作失去总量约束。

**把计费身份作为设置开放。** 修改身份会把计费转移到另一项策略，而不是对保留的已计费用量应用新的上限。

## 影响

根 agent 可以使用完整的共享额度，委派工作仍会消耗该额度。把上限降到已记录用量以下，会暂停下一次预留，而不删除历史。提高上限会在同一计费阶段增加可用容量，但不会自行启动工作。持久化和注册释放仍遵循[设置服务现有的所有权规则](../architecture/2026-09-01-settings-service-write-and-disposal-integrity.zh.md)。

## 验证

完整的[会话预算测试](../../../../packages/core/session/tests/request-budget.spec.ts)、[agent loop 暂停与恢复测试](../../../../packages/core/agent-loop/tests/request-budget.spec.ts)以及[文件持久化设置测试](../../../../packages/core/agent-loop/tests/request-budget-settings.spec.ts)共同通过，共 43 项。测试覆盖根 agent 与委派 agent 的精确计数、经身份验证的人工续期、提高或降低上限时保留已计费用量、保存／重置／重启后的持久性、拒绝由 agent 发起的写入，以及注册释放。计费改动及这些测试的定向类型感知 lint 和类型检查通过。

聚焦的发布分支还通过了 27 个完整文件中的 383 项测试，覆盖设置生命周期、远程事件、spine 配置和目录契约。官方构建完成并生成 292 项客户端产物。三项真实浏览器测试覆盖英文和中文预算卡片的渲染、保存／放弃／重置行为、动态移除、无障碍以及启动请求上限。

本次修订的上限行为、设置控件以及独立的 NES 改动尚未在已安装服务中完成验证。这些检查确认聚焦的源码行为，并不证明 NES 运行或已安装服务正确。
