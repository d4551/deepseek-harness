# Agent Note: Stop the UI gates certifying their own holes

Status: implemented

[English](2026-08-31-ui-gates-stop-certifying-their-own-holes.md) | 中文

## Problem

三道关卡在干净的工作树上都是绿的，却漏掉了它们声称要拒绝的大部分情况；此外还有第四个缺陷：一个从未解析成功的令牌掩盖了一次对比度回归。

`scripts/client-ui-ssot.ts` 中的 reduced-motion 检查只问两件事：样式表里有没有提到 `prefers-reduced-motion`，以及那个媒体块里有没有*任意*一条规则停下*任意*一个动画。有六个探针本该失败却通过了：两个选择器有动画而只有一个守卫、守卫写在媒体块之外、`animation-iteration-count: infinite` 长写形式、守卫指向另一个选择器、守卫排在它要覆盖的规则之前，以及一个只改了颜色的媒体块。正则 `@media[^{]*prefers-reduced-motion[^{]*\{[\s\S]*$` 一直匹配到文件结尾，所以样式表中后面任何一处 `animation: none` 都会被算作守卫。

`scripts/verify-client-ui-i18n.ts` 中的 i18n 检查只能通过追踪 `function` 声明的参数流向 `textContent` 或 `innerText` 来发现被绘制的文案。它漏掉了最直白的 `el.textContent = 'literal'`，也漏掉了 `innerHTML`、`insertAdjacentText`、`createTextNode`、`append`、`setAttribute('aria-label', …)`、`placeholder` 与 `title` 赋值、箭头函数与类方法形式的绘制点，以及除最后一个之外的所有参数（`sinks.set(name, index)` 会覆盖前一个）。它的扫描文件集只覆盖 `packages/client/*`，外加那些恰好在 `src/client` 下含有 `.tsx` 的包，因而有 67 个文件从未被扫描，其中包括一个通过 `innerHTML` 绘制八条未翻译文案的预启动选择器。

`--dsw-alias-label-error` 此前被添加为指向 `--dsw-alias-state-error-primary`。该档位在浅色下是 `red-600`（白底 4.4976:1），在深色下是 `red-400`（`bg-layer-2` 上 4.24:1，`bg-layer-3` 上 3.68:1）——三者都低于 WCAG 1.4.3 的下限。在该令牌存在之前，`var()` 无法解析，整条声明被丢弃，文案继承 `label-primary`，深色下为 11.57:1。定义这个令牌反而让已上线的错误文案更糟。`--dsw-alias-fill-l2` 同源：它的深色值 `bluish-800` 恰好就是 `--dsw-alias-bg-layer-3`，也就是这个 chip 所处的菜单，于是 chip 与自身背景的对比度是 1.00:1。

`zod` 4.5.4 在首次解析穿过一条 schema 引用链时会传递性地解析整条链。生成的递归泛型每次解引用都会构造一个全新的实例，因此 `Self<T>` 引用 `Self<T>` 形成的是一座无尽的塔而不是一个能闭合的环，解析时栈溢出。

## Decision

**守卫回应的是选择器，不是整张样式表，而且只对提出请求的读者生效。** `cssRules` 对样式表做花括号配对，进入 at-rule 内部、跳过 `@keyframes` 的关键帧，并记录外层 `@media` 是否在请求更少的动效。每一个声明了无尽动画的选择器，都必须被排在它*之后*的停止规则按名字点到，或者被 `*` 覆盖。简写与长写两种无尽形式都会被识别；有限的迭代次数、`animation: none`、`animation-play-state: paused`，以及不超过一毫秒的时长，都算作停止。仅凭特性名会在四处判断错：`not (prefers-reduced-motion: reduce)` 会把查询取反，从而把守卫记在并未提出该请求的读者头上，因此任何否定都会使该 prelude 失去资格；`(prefers-reduced-motion: no-preference)` 是相反的查询，会把守卫记在并未提出该请求的读者头上；字符串里的花括号不是一个块，把它计入会让其后每一条规则都落进错误的块；而组合器两侧的空白并不属于选择器的身份。

**从未经过绘制点的文案同样是文案。** 放进组件状态的字面量，会在该状态被渲染的任何地方显示出来，这是赋值规则看不到的。这对绑定的两端都算——`useState` 的初值与 setter 一样——并且 setter 通过这对绑定自身的解构找到，而不是靠猜命名约定。状态里也放键名和 id，因此单个词按形状判断：内部大写、分隔符或数字，正是 `ArrowRight` 和 `plugin-card-open` 的写法，而 `Saved` 不是。若改为要求必须含空格，则会放过属性规则本就会拒绝的每一个单词标签。

**绘制点是那次赋值，而不是那个辅助函数。** 文案在被绘制的地方就被报出：任何 `TEXT_SINK_PROPERTIES` 属性赋值右侧的字面量、传给 `insertAdjacentText`/`createTextNode`/`append` 等方法的实参，以及 `setAttribute` 对承载文案的属性所设的值。针对辅助函数的参数追踪仍然保留，现在会读取函数声明、类方法和具名箭头函数，保留每一个被绘制的参数位置，并匹配通过接收者发起的调用。扫描文件集是仓库中每一个 `packages/*/*/src/client` 目录树。

**标记是结构，不是文案。** 一个把文案插值进去的模板，字面量部分只剩下标签，而标签名不是文案。`markupText` 去掉标签语法，保留标签之间的文本，以及 `aria-label`、`title`、`alt`、`placeholder` 及其 ARIA 同类属性的值——匹配时带左边界，因此 `data-title` 不在其列——单引号与双引号一视同仁，因为模板写在反引号里，两种写法同样常见。写在行内的文案依然会被拒绝，而纯结构的模板不会。

**一次观测，两个出口，两种形状。** 那条渲染失败信息此前也在被绘制：面板在它前面放一个翻译过的标签，然后把整句英文接在后面，且位于 `role="alert"` 之中。`DynamicCordisRenderFailureView` 新增 `cause`——去掉英文外壳的崩溃文本及其重定向提示——供页面本地出口使用，而线上记录的 `message` 仍为模型逐字保留。面板渲染 `cause`，因此被豁免的那段文本不再展示给任何人。

**诊断文本逐条列出。** `NON_COPY_DIAGNOSTICS` 列出三对精确的（文件，文本）：一个向开发者工具标识浏览上下文的 realm 标签、一个无法序列化的 console 实参的占位说明，以及 Host 为模型保留的渲染失败行。最后一条受 model-facing contract 规则约束、必须逐字固定，翻译它恰恰会破坏该规则所保护的东西。以精确文本为键意味着这些文件中的任何其他字符串仍会被拒绝。

**错误文案获得自己的色阶档位。** 新增 `red-700`（浅色，白底 6.03:1）与 `red-300`（深色，在消费者会用到的最浅表面档位上 4.51:1，在实际渲染所处的两个档位上分别是 6.55:1 和 5.68:1）。`state-error-primary` 仍保留 `red-400`，用于边框与填充，它们对应的是 3:1 的非文本下限。深色 `fill-l2` 改为 `bluish-750`，与菜单相差一档而不再相等：与表面的分离度为 1.26:1，而浅色那一对的分离度是 1.16:1，其上的 `label-secondary` 为 6.37:1。

**一次实例化就是一个 schema。** `SchemaEmitter` 通过一个以实参 schema 为键的生成记忆表来输出泛型声明，于是自引用会解析到正在构造的那一次实例化。记忆表在构造完成之后写入，因为自引用只会经由 `z.lazy` 到达，而它在定义构造期间不会运行。而只有实参本身稳定，标识才稳定：把实参写死的自引用（`Self<T>` 内部的 `Self<string>`）每次解引用都会重新求值那个表达式，完全命中不到记忆表，因此不读取任何类型参数的实参会被提取为一个模块绑定、只生成一次并按名引用。所有生成的绑定——schema、参数、被提取的实参——都从同一个标识符集合分配，因为声明完全可能就叫 `argument0` 或 `type0`，否则同一个名字会被声明两次，或在工厂内部被悄悄遮蔽。真正无法由任何记忆表闭合的，是用自身参数构造出来的自引用（`Grow<V>` 的成员是 `Grow<V[]>`）：它在每一层都命名一个不同的类型，因此生成器直接拒绝它，而不是产出一个在解析时栈溢出的 schema。

**每个依赖在工作区只有一个版本。** `checkSingleExternalVersion` 要求每个工作区清单对同一个外部依赖只声明一个基础版本，比较的是基础版本，因此精确锁定与同一基础版本的 caret 属于同一个选择。`vendor/` 豁免：那些清单是上游的固定副本，只通过 vendor 同步流程变动。

## Consequences

reduced-motion 规则现在会让此前通过的六个探针全部失败，同时仍然接受正确的样式表、`@keyframes` 关键帧、被完整回应的逗号选择器列表以及 `*` 守卫。i18n 规则可捕获十四种绘制形式，忽略 `data-*` 属性和表单 value，覆盖 621 个文件。多进程套件的超时预算归文件所有，而不是取决于哪些用例记得去申请：`install-lefthook` 有二十二个会派生进程的用例挂在该 lane 的 30 秒默认值上，这正是整套测试时红时绿的原因。预启动预览选择器拥有自己的 `en`/`zh` 字典；它自行解析浏览器偏好，而不是跨越这个独立打包的原型刻意不具备的包依赖边去引入一个解析器。

两条陈述不实的注释已被更正：`label-quaternary` 声称只有一个消费者，实际有两个，第二个是一个启用状态的链接，其下划线现已改为 `currentColor`；`StatsLine.module.css` 记录的 1.1:1，真实值是浅色 1.25:1、深色 1.41:1。

把对象字面量文案规则扩展到 `.ts` 文件的做法试过并已回退：它会暴露 228 个候选，其中绝大多数是面向模型的 catalog `description` 字段，并非读者可见的文案。那需要一次单独限定范围的处理，而不是一次性放开。

`website/` 保持在 `vite ^5.4.14`，因为 VitePress 1.6.4 就是当前发行版并依赖该范围；工作区版本规则覆盖 `packages/*` 与 `apps/*`，并不涉及它。VitePress 的客户端入口以裸说明符导入 `vitepress-plugin-mermaid/Mermaid.vue`，隔离式安装下无法从 VitePress 自身目录解析到它，因此站点配置将其别名指向该站点实际安装的那份副本。

## Alternatives considered

**让 reduced-motion 规则继续用正则、只是把模式写得更宽。** 已否决：那六个漏洞并不是一个模式对应一个。顺序、选择器身份、块归属都属于结构，而看不见花括号的模式，这三者一个都看不见。

**为那三条诊断文本豁免整个文件。** 已否决：`runtime.ts` 超过一千行，文件级豁免会把日后加进去的真实文案一并吞掉。列出精确文本只需三条记录，且不会自行扩大。

**把 `--dsw-alias-label-error` 指向 `label-primary`。** 这样能满足对比度下限，但错误文案将不再是红色，而那正是这个令牌存在的意义。在同一色阶中新增一档，信号和下限都能保住。

**把 `zod` 退回 4.4.3。** 栈溢出随 4.5.4 出现，但回退只会掩盖一个生成代码的缺陷而不是修复它：不共享的实例化本身就是错的，与哪个版本发现它无关。

**为整个 `vitepress-plugin-mermaid` 包而不是那一个组件设置别名。** 出问题的导入是 VitePress 自身入口中的单个说明符；对包根设别名会连带改写配置文件自己的导入，而后者本来就能解析。
