# Agent Note: 拒绝空不变量安装器

Status: implemented

[English](2026-09-16-reject-empty-invariant-installers.md) | 中文

## 问题

空不变量安装器只保留包名，不检查包的行为。把说明性注释当作执行约束的证据，会让文档掩盖缺失的检查。仓库禁止空操作，因此包门禁必须报告这种缺失的实现。

## 决策

[包不变量门禁](../../../../scripts/package-invariants.ts)拒绝函数体为空的安装器，包括函数表达式和通过 `Object.assign` 携带注入服务的安装器。注释不构成豁免。发布、完整名称注册、Loader 形状和失败报告器要求仍然强制执行。

这移除了[有意义的包不变量约定](../architecture/2026-07-19-package-invariant-runtime-contracts.zh.md)中的空安装器许可。该笔记仍然规定有意义的事件/数据检查，并禁止人为添加的方法存在性断言。注册名称、在测试中调用空函数或断言固定示例，都不能代替检查包拥有的运行时关系。

## 验证

所属门禁测试证明：带注释和不带注释的空箭头函数、空函数表达式以及带注入声明的空安装器都会失败。安装真实事件监听器的实现仍被接受。全仓库扫描列出所有剩余空安装器，并以失败状态退出；这些发现仍属于实现债务。

## 考虑过的替代方案

- **保留基于注释的豁免。** 拒绝，因为说明不是可执行检查，也与禁止空操作的要求冲突。
- **用通用存在性断言填充安装器。** 拒绝，因为这些断言重复类型/加载检查，却不能检测不一致的运行时状态。
- **删除配套插件以消除发现。** 拒绝，因为这会放弃现有的包发布和注册要求。

## 后果

即使某个包没有明显的可观察状态，门禁也会暴露缺失的检查。结构检查不能证明语义正确：每个配套插件仍需要源码评审以及有效/无效运行时证据。门禁修复并未实现剩余配套插件，也不能证明完整覆盖率、变异测试达标或全部检查通过。
