# Agent Note: 完整源码质量门禁

Status: implemented

[English](2026-09-16-complete-source-quality-gates.md) | 中文

## 问题

当配置遗漏源文件时，覆盖率百分比不能证明完整性。不带插桩的成功测试运行不能补足缺失测量。可选作业和由环境变量控制的类型检查，也使绿色汇总结果无法证明所有必需检查均成功。

## 决策

覆盖率清单独立于 Vitest 配置，发现包源码目录下的所有 JavaScript 和 TypeScript 文件。配置验证器要求完整的纳入模式、空排除列表、自动附加子进程和工作线程的 V8 测量、失败时生成报告，以及全部四项指标无条件逐文件达到 100% 的阈值。测量拒绝缺失的文件结果和过期输出，并保留相同阈值。

每个调度门禁都会传播失败。类型检查没有环境变量绕过开关。Windows 检查纳入必需的 CI 汇总。绑定进程的套件保留独立工作进程，同时参与插桩覆盖率。CI 在一次覆盖率调用中运行完整套件。涉及进程全局状态和原生生命周期行为的套件仍需进程隔离；[Windows 记录](../process/2026-08-08-native-windows-pull-request-ci.zh.md)保留其平台职责理由。

覆盖率等待完整应用构建，因为套件包含生成包导入和打包后的 Worker 执行。独立覆盖率聚合流程在 Linux 和 Windows 上均负责自身构建；主聚合流程复用已有构建依赖。完整本地测试门禁等待应用与 Web 两项构建写入完成。这取代[消费方独立构建](../process/2026-07-30-independent-ci-consumer-build.zh.md)中只准备源码的覆盖率策略，同时保留独立作业分配。缺少产物会使验证失败。

Worker 沙箱验收在原生浏览器 Worker 内，通过映像打包器和模块加载器加载真实提供方包。生产 Worker 安装自身进程环境并启动命令 Worker；测试验证工作区及临时目录写入、工作区外写入拒绝、只读行为、显式完全访问及并发策略隔离。浏览器错误和警告均使验收失败。这些行为证据不能替代浏览器执行包的源码覆盖率。

主机 TypeScript 项目纳入快照驱动程序。它们的导入同时参与类型检查和 Vite 的源码路径解析，因此快照收集能够执行记录会话的断言。

基于语法的源码审计拒绝注释中禁用 lint、TypeScript、覆盖率和变异检查的指令，以及每个 catch 子句。其 Git 工作树清单纳入包、应用、脚本、快照、vendor、原生代码、网站、CI 和根配置中已跟踪及未跟踪的 JavaScript 与 TypeScript；新源码目录也会参与。形似指令的字符串和正则表达式属于数据。这取代[机械质量门禁](../process/2026-06-11-quality-gates.zh.md)对指令的许可。解释性注释不会改变判定。解析错误和空源码分组都会使审计失败。

本决策取代已归档的[欠债标记策略](../../archived/testing/2026-09-06-coverage-debt-markers.md)、[测量策略](../../archived/testing/2026-09-12-coverage-debt-measurement.md)和[独立重型套件门禁](../../archived/process/2026-07-31-coverage-exempt-heavy-suites.md)。这些记录描述已移除的策略，不是当前依据。

可选分区协调器、对应命令与报告合并路径均已移除。每个部分分片都会留下未执行的其他源文件，因此无法通过未改变的完整源码阈值。合并报告成功不能抵消该失败。[已归档的分区记录](../../archived/process/2026-08-18-in-job-partitioned-coverage.md)保留已退役的机制；`scripts/coverage-command.ts` 保留不经过 shell 的测量进程、流式输出、有界诊断尾部，以及独立的退出、信号和启动错误结果。

历史分区试验报告：Windows 双子进程约耗时 405 秒，16 子进程耗时 112.66–122.01 秒，Linux 双子进程两次分别耗时 276.68 和 282.27 秒。较大的进程内池还曾产生 worker 退出、fixture（测试前置数据）不稳定和 Node 24 CJS lexer 故障。这些较早的清单和阈值策略无法证明当前性能或完整源码通过结果。并发决策必须依据固定配置下已完成的运行；进度缓慢本身不足以重启运行或增加进程数。

## 考虑过的替代方案

**保留附带理由的排除项。** 已记录的遗漏仍使行为缺乏测量。记录理由不能满足所要求的源码覆盖率。

**使用降低的阈值测量。** 当证据不完整时，测量命令必须失败。单独的宽松配置会使成功结果的含义不明确。

**保留可选分片或工作流级分片。** 分片无法独立满足完整源码阈值。工作流级分片还会重复设置，并需要报告传输与合并依赖。移除协调器能保留单次覆盖率调用，同时不削弱任何结果。

**保留平台失败的建议性质。** 汇总必须代表每个必需的平台检查；Linux 成功不能证明 Windows 行为。

**用主机进程原语代替 Worker 执行。** 只替换进程执行会保留主机平台，并选择不同的隔离后端。覆盖平台或探针判定不能证明部署后的 Worker 会隔离命令。

## 后果

严格门禁暴露尚存的违规和覆盖率缺口。安装这些检查并不解决发现的问题，也不证明全仓库分数达标。修复需要受影响源码的行为测试和实测结果；仅验证配置不能提供其中任何一项。
